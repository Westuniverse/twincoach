# 动作协议

## 深蹲规则

live、recorded 和 replay 入口使用 squat_process_v1。规则统计完整动作过程的阶段、底部窗口、缺失区间、时间与权重覆盖，并据此生成反馈。

最深帧评分与全过程评分属于不同量表，不应直接混合比较。阈值属于可配置的工程规则，需要结合使用者、相机布局与标注数据评估。

每个支持的动作必须定义：

- 摄像头位置和有效视野；
- 必需关键点与置信度阈值；
- 阶段状态机与滞回阈值；
- 完成一次计数的规则；
- 可测偏差与无效条件；
- 个体标定字段；
- 确定性测试序列；
- 局限性以及禁止宣传的结论。

深蹲是系统支持的动作；其他动作需要各自的观测与计次协议。深蹲基线由侧视角提供深度、躯干和矢状面指标，由正视角提供左右对称和额状面指标。任何阈值只有在单位、坐标定义、来源和测试用例齐全后才能正式接受。

用户界面的百分比名称为**动作规范度/规则符合度**。它不是姿态模型准确率，必须同时显示观测置信度。每个分项必须能够展示实际观测值、单位、理想范围、容差和权重；不能只显示一个无法追溯的总分。评分权重和阈值在固定视频测试完成前均属于暂定工程值；条件允许时还应邀请合格教练复核。

关键点轨迹、人工计次和可选逐次评分使用 `scripts/evaluate_score_dataset.py` 做固定数据评估；清单格式、指标边界和最小覆盖见 `docs/scoring_validation.md`。计次不匹配的样本不强行计算逐次评分误差。

深蹲跟踪还必须遵守断流恢复规则：相邻同步姿态对超过版本化配置 `maximum_tracking_gap_ms` 时，进行中的半次动作立即失效，恢复后的非站立姿态不能直接延续旧阶段。`squat_v0.1.json` 当前使用 1000 ms 暂定工程值；它用于阻止断流前后状态拼接，不是人体动作阈值，需要通过固定输入与断流测试评估。

缺失观测的默认处理为`missing_tracking_policy=reset`。可选值`hold`只在最后有效
膝角距当前不超过同一1000ms上限时暂存相位；无效帧对外为unknown，不补造角度、
推进计次或更新最深点评分。持续无效帧不能刷新期限，超过期限立即丢弃半次动作。
此时`SquatTracker.phase`仅表示内部最后接受的阶段，当前观测状态以`SquatUpdate.phase`
为准。hold 为显式配置，默认不启用。

另有默认关闭的`require_front_ankles_below_knees`可选条件：可信的四个正面膝/踝点
须满足两个踝点均低于两个膝点；点不足为未知，原有hold只允许有界缺失。可信点
明确违反时立即取消半次动作，即使hold也不能跨过它。该图像次序不是地面接触或
3D判定，且不改变侧面角度、置信度及断流门限；该条件为可选配置，默认不启用。
