# 动作协议

状态：深蹲工程基线已实现；阈值仍待固定视频实验和专业复核。

2026-10-24新增可显式回退的过程规则：live/recorded/replay默认squat_process_v1，
保留原reset/front-order关闭；实验过程候选另保留hold/front-order。全过程统计边界、
阶段适用、底部窗口、缺失区间、时间与权重覆盖及反馈规则见
0080（原工程参考：`decisions/0080-process-squat-scoring.md`）。旧配置继续使用最深帧算法，
不可将两个算法的得分当成同一量表直接比较。新门限仍为暂定工程值。

每个支持的动作必须定义：

- 摄像头位置和有效视野；
- 必需关键点与置信度阈值；
- 阶段状态机与滞回阈值；
- 完成一次计数的规则；
- 可测偏差与无效条件；
- 个体标定字段；
- 确定性测试序列；
- 局限性以及禁止宣传的结论。

初始候选包括双视角深蹲、肱二头肌弯举和侧视角平板支撑。深蹲基线由侧视角提供深度、躯干和矢状面指标，由正视角提供左右对称和额状面指标。任何阈值只有在单位、坐标定义、来源和测试用例齐全后才能正式接受。

用户界面的百分比名称为**动作规范度/规则符合度**。它不是姿态模型准确率，必须同时显示观测置信度。每个分项必须能够展示实际观测值、单位、理想范围、容差和权重；不能只显示一个无法追溯的总分。评分权重和阈值在固定视频测试完成前均属于暂定工程值；条件允许时还应邀请合格教练复核。

关键点轨迹、人工计次和可选逐次评分使用 `scripts/evaluate_score_dataset.py` 做固定数据评估；清单格式、指标边界和最小覆盖见 `docs/scoring_validation.md`。计次不匹配的样本不强行计算逐次评分误差。

深蹲跟踪还必须遵守断流恢复规则：相邻同步姿态对超过版本化配置 `maximum_tracking_gap_ms` 时，进行中的半次动作立即失效，恢复后的非站立姿态不能直接延续旧阶段。`squat_v0.1.json` 当前使用 1000 ms 暂定工程值；它用于阻止断流前后状态拼接，不是人体动作阈值，后续仍需固定视频和板端断流实验复核。

缺点处理的默认值仍为`missing_tracking_policy=reset`。显式实验值`hold`只在最后有效
膝角距当前不超过同一1000ms上限时暂存相位；无效帧对外为unknown，不补造角度、
推进计次或更新最深点评分。持续无效帧不能刷新期限，超过期限立即丢弃半次动作。
此时`SquatTracker.phase`仅表示内部最后接受的阶段，当前观测状态以`SquatUpdate.phase`
为准。该候选及暂定录像结果见0051（原工程参考：`decisions/0051-bounded-missing-observation-candidate.md`），
尚未改变正式配置或部署，不能据此宣称人体计次/评分已验收。

另有默认关闭的`require_front_ankles_below_knees`实验条件：可信的四个正面膝/踝点
须满足两个踝点均低于两个膝点；点不足为未知，原有hold只允许有界缺失。可信点
明确违反时立即取消半次动作，即使hold也不能跨过它。该图像次序不是地面接触或
3D判定，且不改变侧面角度、置信度及断流门限；暂定高抬腿反例见
0056（原工程参考：`decisions/0056-front-ankle-knee-order-candidate.md`），未启用为现役默认。
