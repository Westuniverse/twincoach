# 架构选择与优化依据

## 系统目标

目标是让两路姿态、动作反馈和数字人显示在 KV260 上连续协作。评价以新姿态对完成确认、源龄和停顿为主，同时检查资源与时序。采集 FPS、单核耗时和绘制次数分别保留自己的边界。

## 软硬件划分的理由

| 选择 | 处理的问题 | 代价与证据 |
| --- | --- | --- |
| 正面与侧面联合观测 | 单一视角难以同时提供深度与左右对称信息 | 增加采集与双路推理负载；[动作协议](exercises.md) 说明指标归属 |
| DPU 前段与定制 PL 后段 | 将姿态推理放在板端，并连接匹配的计算与数据搬运接口 | 依赖模型、W/P、程序与固件匹配；[接口](interfaces.md) 给出边界 |
| ARM 几何与规则评分 | 保留可配置、可解释的动作逻辑 | ARM 工作仍可能影响端到端吞吐 |
| PL 蒙皮与 Mali 绘制 | 将角色变换与光栅化分配给对应执行单元 | 显示提交和完成等待需要纳入完整测量 |
| 按源身份计量 | 排除重复显示被误算为新结果 | 需要完整保留源身份与完成确认；[统计技能](../skill/pipeline-metrics/SKILL.md) 可独立复用 |

这些是本系统的组合设计依据，不主张各个组件本身为首次提出，也没有独立双视角准确率增益实验。

## DDR 互连对照

同一组 2698 张 JPEG、45.019937339 秒输入，窗口为 [15,44) 秒。计算时钟、RTL、模型与量化保持相同，改变 DDR 交换与 HP0 出口时钟。

| 指标 | 100 MHz | 200 MHz | 差值（200−100） |
| --- | ---: | ---: | ---: |
| 新姿态对/s | 23.551724 | 23.310345 | −0.241379（−1.02%） |
| P95 源龄 ms | 292.446460 | 291.764929 | −0.681531 |
| 最大确认间隔 ms | 111.343805 | 126.086863 | +14.743058 |
| 最低滚动一秒更新数 | 20 | 20 | 0 |

该次对照没有显示完整链路吞吐收益。两组各为一次测量，没有重复测量的置信区间；处理子集不同的局部耗时不用于计算独立算子加速比。数据见 [comparison.json](../data/comparison.json)，完整上下文见 [DDR 分析](ddr.md)。

[项目性能记录](results.md) 的 23.034483 次/s 来自另一次运行，不作为上述 A/B 的第三个变体，也不与其混算收益。

## 资源约束

| 资源 | 使用 / 可用 | 占比 |
| --- | ---: | ---: |
| LUT | 78404 / 117120 | 66.94% |
| FF | 115916 / 234240 | 49.49% |
| CLB | 14629 / 14640 | 99.92% |
| BRAM36 等效 | 139 / 144 | 96.53% |
| DSP | 655 / 1248 | 52.48% |
| URAM | 64 / 64 | 100.00% |

表格可由 [结果复算工具](../build/results.py) 从实现报告提取。CLB、BRAM 和 URAM 比 LUT 或 DSP 更接近容量上限，新增并行计算需要先考虑存储与布局空间。setup/hold 裕量为 +0.017/+0.008 ns；这些数值对应保存的实现报告，不代表任意参数修改后仍满足时序。

## 后续选择标准

优先定位 ARM 解码、几何准备、GPU 提交与阶段等待；以相同输入和完成边界比较吞吐、源龄及最大停顿。只有端到端收益与数值结果相符时才采用改动。功耗、真人准确率和长期稳定性需要各自的测量，现有数据不推导这些结论。
