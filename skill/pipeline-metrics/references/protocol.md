# 统计协议

## 输入

CSV 列：`id,source_ns,done_ns`，可选 `epoch`。身份为 `(epoch,id)`；相同身份只取最早的完成确认。时间戳为整数纳秒。

| 字段 | 含义 |
| --- | --- |
| id | 一次输入的稳定身份，不是绘制次数 |
| epoch | 源编号重用时区分不同采集区段 |
| source_ns | 数据源进入被测链路的时刻 |
| done_ns | 消费者确认对应结果完成的时刻 |

工具也接受含 `replay_start_ns` 和 `final.presentation_samples` 的项目原始 JSON。JSON 使用 capture_epoch 和 source_ids 构造身份，只消费 fresh_pose_pair 标记的确认。

## 窗口与公式

设原点为 O，窗口为 [a,b)，所有量转换到相同的纳秒时钟。选择 `O+a×10⁹ ≤ done_ns < O+b×10⁹` 的新输出。

- 新输出数 N：选中且去重后的确认数量。
- 窗口吞吐：N/(b−a)。它不是单算子理论吞吐。
- 单样本源龄：(done_ns−source_ns)/10⁶，单位 ms。
- P95：升序源龄的 `floor(0.95×(N−1))` 号元素。
- 最大确认间隔：选中确认按完成时间排序后的相邻差值最大值。

相同源在窗口前已经完成、窗口内只重复显示时，不重复计入。只有一个确认时最大相邻间隔为 0；没有确认、非法窗口或完成早于源时间时不输出有效指标。

## 原点

CSV 默认原点为 --origin-ns。使用 --origin-first 可选择最小 source_ns。JSON 使用 replay_start_ns。改变原点不改变实际时间戳，只改变窗口定位。

## 运行

```bash
python3 scripts/measure.py trace.csv --origin-first --start 0 --end 10
```

源数据可以来自 pynq-pipeline 的 --trace，也可以由其他项目采集。工具不要求 PYNQ。

## 失效条件

- 不同机器的墙钟未经同步，不能相减作为源龄。
- id 重用但未提供 epoch，会把不同输入去重。
- done_ns 只是入队时间时，只能报告入队边界，不能称为计算完成。
- GPU 完成确认不等同于物理屏幕扫描。
- 少量样本不能说明长期稳定吞吐；不同输入、模型、窗口和完成边界不能直接计算加速比。

## 工程观察

重复画面可能拥有更高显示 FPS，却没有产生新姿态。源身份去重与固定窗口统计把“画面刷新”和“新输入完成”分开，是该工具的直接用途。示例数据及测试验证去重、窗口边界和时钟约束，不把合成样例当作真实设备性能。
