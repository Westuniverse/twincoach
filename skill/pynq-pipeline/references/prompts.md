# 模型助手任务模板

以下模板用于提供约束和可审阅输出，不要求模型预先给出性能或通过结论。

## 从接口接入

> 使用 pynq-pipeline 技能。根据我提供的 HWH/IP 列表、寄存器说明和数据格式生成契约。明确 DMA 的 simple/SG 模式、字节数、TLAST、启动和缓存职责。缺少的信息列为未确定项，不猜测寄存器偏移。先以给定的独立黄金向量完成软件检查，不下载位流。

期望输出：契约 JSON、输入与黄金向量来源、需要修改的接口项、可执行检查命令。

## 对另一题目复用

> 将同一工具用于一个参数化整型信号处理核。保持通用脚本不变，只替换 IP 名称、数据类型、寄存器和黄金向量；若软件参考不支持该操作，说明最小扩展点。区分软件复用与实板验证，不把模型结果写成硬件测试。

期望输出：新契约与向量、实际命令结果、原样复用与需要扩展的模块对照。

## DMA 故障

> 根据结果 JSON、HWH 和 DMA 状态定位失败阶段。按元数据、身份、参数、接收提交、发送提交、完成与释放顺序检查。保留原始失败，只有具备相应授权时才操作设备；不要通过自动重试或重配 PL 掩盖问题。

期望输出：首个失败边界、支持判断的具体字段、下一项最小检查及恢复所需条件。

## 性能比较

> 根据两份同格式 CSV 使用 pipeline-metrics 比较。先核对源身份、epoch、时钟、输入与完成边界，再使用相同固定窗口统计。若条件不同，分别报告，不直接计算加速比。

期望输出：输入条件表、可复算 JSON、吞吐/源龄/间隔比较及适用范围。
