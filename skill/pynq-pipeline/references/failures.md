# 故障定位

| 现象或触发条件 | 应检查的边界 | 动作 | 不能据此得出的结论 |
| --- | --- | --- | --- |
| bit/HWH 缺少或 stem 不同 | 工程元数据 | 找到匹配产物后再 inspect | 文件名相近不代表相同设计 |
| IP 路径解析失败 | 契约与 Overlay 层级 | 对照 ip_dict 和 DefaultHierarchy 属性 | 不应尝试写其他地址 |
| Overlay 未加载 | 配置状态 | 读取状态；有部署授权时显式 --program | 不自动替换现役 PL |
| identity 不符 | 控制接口 | 停止，确认位流与寄存器表 | 身份值不能随意改成实际读值来“通过” |
| transfer 长度拒绝 | 字节数与硬件容量 | 对照 dtype×count、max_bytes 和 DMA 配置 | 缓冲足够大不代表硬件计数器足够 |
| 接收 wait 不完成 | AXI stream 协议 | 检查 TLAST、数据拍数、背压、时钟与复位 | 单纯增加等待时间不能修复缺失的 TLAST |
| 输出为旧值 | 缓存与完成语义 | 确认驱动完成 invalidate；自定义驱动需单独定义职责 | 不应在多层重复刷新来掩盖所有权问题 |
| 正数正确、负数错误 | 位宽与符号 | 核对 dtype、打包、定点及符号扩展 | 不修改黄金值来匹配错误输出 |
| 部分前缀正确或收到短帧 | 长度、帧尾与输出容量 | 核对 recvchannel.transferred 与契约字节数，检查提前 TLAST | 前缀一致不等于整帧通过 |
| 软件通过，板端失败 | 后端差异 | 按设备地址、接口与协议定位 | mock 不验证布线、时钟或物理缓存 |
| 平均速率高但停顿明显 | 性能边界 | 使用独立轨迹分析源龄与确认间隔 | 输入 FPS 或绘制次数不等于新结果更新 |

## 缓冲释放

正常路径等待两个通道完成，再读取 RX 并释放缓冲。异常路径调用驱动 stop；只有停止确认后才释放。停止本身失败时，会话保留缓冲并禁止继续提交。

PYNQ 的阻塞 wait/stop 没有通用的事务恢复保证。对于协议挂起，应按实际设计恢复 DMA/PL，确认停止后再结束资源所有者。工具不通过重复提交、强杀进程或自动重配整片 PL 来制造成功记录。

## 从工程观察到可复用规则

- 实际源码引用与仓库目录不一致 → 显式契约和运行路径，不按文件名猜测。
- 显示刷新与新数据完成混淆 → 独立源身份和完成确认。
- 部分工具命令失败但正式产物已保存 → 根据失败阶段复用证据。
- 多层重复检查与对象转换增加开销 → 静态检查集中在契约入口，缓存由确定的驱动边界负责。
