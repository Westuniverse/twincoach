# 验证覆盖与证据

## 能力与证据

| 能力 | 可执行证据 | 覆盖范围 |
| --- | --- | --- |
| 不绑定单一业务 | copy 与 affine 独立样例 | 改变任务、IP 名称和数据类型 |
| 不依赖项目目录 | 将整个技能复制到独立目录执行 | 工具没有 TwinCoach 路径或模型依赖 |
| 明确输入输出 | contract 与 vectors 文件 | 类型、字节数、容量、寄存器和黄金结果 |
| PYNQ 适配 | API 替身调用真实适配器 | Overlay 参数、层级解析、接收先行、驱动缓存职责和释放顺序 |
| 失败可定位 | 契约拒绝、身份不符、数值差异、短帧与停止失败测试 | 不误报通过，不释放仍在运行的缓冲 |
| 报告不夸大 | JSON/Markdown 明确 backend 和 hardware_executed | mock 不输出硬件通过或硬件吞吐结论 |
| 可与其他工具组合 | CSV 源身份与纳秒时间戳 | pipeline-metrics 不要求 PYNQ 或本项目 |

## 测试层次

1. **软件模型**：两组明确给出的黄金向量与 MockBackend 比较。
2. **API 替身**：软件对象模拟 Overlay、DMA 与 Buffer，运行真正的 PynqBackend，检查调用及所有权语义。
3. **独立目录**：仅复制技能目录，执行 inspect、run 和 report。
4. **实际硬件**：需要目标板、匹配 bit/HWH 和对应 IP，使用者应保存硬件运行结果与自己的工程报告。

仓库测试覆盖前三层。API 替身不加载 PYNQ 驱动，不解析真实硬件 HWH，也不证明 DMA 在实际板卡上的行为。这里没有跨板卡实测或 PYNQ 硬件性能声明。

## 使用者的板端记录

完成硬件验证时，至少保存：契约、独立向量、目标板与 PYNQ 环境、bit/HWH 的来源、IP 映射、结果 JSON、完整输出和故障状态。性能还需保存输入规模、源身份、完成边界和固定统计窗口。

这些证据应让其他使用者区分“能生成调用”“接口和数值通过”“系统可持续运行”三种不同能力。

## 可复算的样例结果

[执行结果](../../../sim/skill.json) 保存软件样例的完整向量、输出、差异与事件，未包含设备性能结论。

| 样例 | 已执行结果 | 说明 |
| --- | --- | --- |
| uint32 copy | 8 个元素、32 字节，逐元素一致 | 包含最高位与最大值 |
| int16 affine | 6 个元素、12 字节，逐元素一致 | 独立黄金结果覆盖正数、零和负数 |
| 合成轨迹，窗口 [0,2) 秒 | 4 个新输出、2 次/秒、P95 源龄 300 ms、最大间隔 700 ms | 包含重复消费、epoch 切换和窗口右边界 |

复算命令见 [使用流程](workflow.md) 和 [统计技能](../../pipeline-metrics/SKILL.md)。这些结果说明工具可处理所给接口与数据，不构成相对裸模型的增益实验或实际硬件加速比。
